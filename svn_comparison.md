# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это файл с 40-символьным хешем коммита (указатель). Создать её — записать 41 байт локально, мгновенно и без сети. В SVN ветка — это копия директории на сервере (`svn copy trunk branches/x`): операция идёт через сервер, а слияние веток исторически требовало ручного отслеживания ревизий (до 1.5 — вообще без merge-tracking), поэтому ветки заводили редко.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN централизованная: история и номера ревизий живут только на сервере, у клиента — лишь рабочая копия последней выгруженной ревизии. Коммит = отправка изменений на сервер, который присваивает ему номер ревизии. Офлайн можно только редактировать файлы и смотреть `svn diff` против локальной «базы».

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- Большие бинарные файлы (геймдев-ассеты, CAD, видео): SVN позволяет выкачать только нужную папку/ревизию, не таща всю историю, и умеет блокировки файлов (`svn lock`) — для неслияемых бинарников это важно.
- Монорепозитории с частичным checkout подкаталогов и строгими правами доступа на уровне путей.
- Legacy-проекты (госсектор, банки), где вся инфраструктура, процессы и аудит завязаны на SVN и миграция дороже выгоды.
- Нужна простая линейная модель с монотонными номерами ревизий (r1234) для регламентов и аудита.
